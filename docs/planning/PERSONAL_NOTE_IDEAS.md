## 1. 用途与决定边界

PersonalNote 的目标是个人知识检索、笔记采集与学习复习的日用工具：在手机上阅读自己的资料，找到可追溯的原文，基于资料提问，整理新笔记，并持续复习。

本次只保存想法，不复制旧项目源码，不删除或重建旧项目，不修改 Obsidian Vault、应用数据或其他项目，不开始 PersonalNote 功能实现，也不改变 DailyLanguage 当前 Gate。

已有统一平台决定继续由 [ADR-0005](../adr/0005-unified-learning-platform-microservices.md) 和[平台架构方案](../architecture/PLATFORM_ARCHITECTURE_PROPOSAL.md)持有；部署决定见 [ADR-0006](../adr/0006-k3s-tekton-deployment.md)。本文不替代它们。后续新增想法应注明来源、日期与是否确认；进入实现前再形成对应 Feature / Slice 合同。

## 2. 要保留的产品需求

| 能力 | 用户希望得到的行为 | 关键边界 |
| --- | --- | --- |
| Obsidian 同步与阅读 | 读取自己的 GitHub Markdown Vault；手机可打开原文，查看来源路径及同步版本 | 外部 Vault 始终只读；同步失败保留上一可用版本 |
| Native Notes | 在应用内创建、查看、编辑、删除独立 Markdown 笔记 | 与 Obsidian 来源分开；同名、非法路径、过期版本不能静默覆盖 |
| 跨来源搜索 | 同时搜索只读 Vault 和 Native Notes；标题、英文技术词、中文词能定位到段落 | 显示来源及版本，支持跳转原文；没有命中要明确说明 |
| 基于资料问答 | 只基于实际检索到的片段回答，展示可打开的引用 | 证据不足时说明；模型生成内容不自动成为笔记或事实 |
| 文本 / URL 采集 | 粘贴材料后先生成可编辑 Markdown 草稿，保留来源 URL 与采集时间 | 用户确认才写入 Native Notes；取消不保存 |
| 主动复习 | 从笔记建立复习项，每天打开应用看到到期任务；自评后保存历史和下次日期 | 用户确认掌握情况；AI 不自行改写掌握度或日程 |
| 手机使用与持久化 | 移动端友好、可安装 PWA；服务重启后笔记和学习记录仍在 | 受控 HTTPS 入口；备份恢复需真实验证 |

无模型配置时，阅读、搜索和复习仍应可用；问答应说明配置缺失。模型失败不应使已有原文不可访问。

## 3. 两种来源的读写边界

### Obsidian：只读资料源

- 原项目确认的来源是私有仓库 `AnnnaSun/interview-knowledge` 的 `main` 分支；后续实现时重新核对实际来源与授权，不在文档中保存凭据。
- 使用限定到目标仓库的只读权限获取快照；不向原仓库提交、推送、删除或修改文件。
- 先下载、校验并建立可用版本，再切换当前快照；失败不清空上一成功快照。
- 原文与引用保留 `OBSIDIAN_READ_ONLY` 来源标记；不能通过修改 ID 或路径绕过只读限制。
- 不把用户本机 Vault 作为应用的可写挂载目录；应用不持有其写权限。
- 后续同步与索引设计需覆盖下载失败、异常归档、路径越界、大小限制、版本标识和并发切换等情况；具体实现另行设计。

### Native Notes：应用管理的可写笔记

- Markdown 作为正文事实来源；索引可重建，不能成为另一套相互覆盖的正文真相。
- 写 API 仅接受 Native 资源标识；目录、ID、权限与只读来源区分。
- 文件路径必须限定在允许根目录内；更新携带上次读取版本，冲突时明确返回，不能静默覆盖。
- 旧方案要求临时文件加原子替换以减少部分写入；重做时保留“不产生半份正文”的目标，按实际存储选择机制。
- 删除必须是显式操作，并设计可恢复的备份；学习事件和 Native 正文不能只依赖可重建索引备份。
- 未来可考虑备份到另一个 GitHub 仓库，使用独立权限；首版不默认做双向同步，不复用 Obsidian 只读凭据。

## 4. 检索、AI 与复习的约束

- 按标题层级和段落组织检索片段，保留来源、文件路径、标题、行范围或等价定位信息、版本及摘录。
- 先用真实笔记问题验收关键词检索；是否增加 embedding、向量索引、重排序等能力另行评估，不因“RAG”名称默认引入整套组件。
- 问答只提供本次所需检索片段；检索文本视为不可信输入，不能获得执行指令或写入权限。
- 引用必须映射到本次实际检索结果，并由服务端校验；不能展示模型编造的文件或引用 ID。
- AI 可辅助生成草稿、问题和解释；笔记保存与掌握度记录仍通过受控业务接口，由用户动作确认。
- URL 采集需限制协议、目标地址、重定向、响应大小和超时，拒绝内网与本机目标；失败不生成正式笔记。
- 复习日程由明确的业务规则计算。笔记知识自评与 Language 的语言能力、Weakness、Level 分别管理，不能合并为第二套通用掌握度真相。
- 模型使用遵循平台 BYOK 决定；GitHub 只读凭据、模型凭据、账号登录凭据分别管理，不进入正文、日志或持久化任务。

以下历史选择不能直接作为统一平台的技术合同恢复：

| 原独立应用选择 | 当前平台已有方向 / 仍待决定 |

## 6. 后续讨论与最小验收入口

开始 PersonalNote 工作时，先核对最新平台决定、当前 Phase / Slice 和本备忘，再由用户决定复用还是重做哪些代码。

1. **确定来源和数据归属：** 目标 Vault / ref、本人账号绑定、Native 存储与备份位置；不能以首个注册者自动继承私人资料。
2. **明确最小认证 slice：** 既有 C25 路线先验证本人可读、其他用户拒绝、匿名拒绝和 Identity 故障拒绝放行；保存本文不替代该合同。
3. **按能力拆分：** 只读同步与阅读 → 关键词搜索 → Native CRUD → 引用式问答 → 采集草稿确认 → 复习。此顺序是原需求拆分参考，具体范围和优先级重新确认。
4. **验证恢复能力：** 同步失败保留旧快照，更新冲突不覆盖，取消草稿不落盘，引用可打开，重启后 Native 与学习记录仍在，备份可恢复。
5. **再讨论扩展：** 向量检索、Native GitHub 备份、离线能力和通知仅在有明确需求时单独决定。

待定项包括具体重做范围、检索质量验收问题集、Markdown / 快照 / 索引的存储布局、数据保留与恢复策略，以及各能力的实现合同。当前均不自动进入开发。
